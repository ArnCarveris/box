# Textures: completion report

## What was built
- `box.texture`: `Texture` loads an image file through stb_image, resizes to a size class, builds a CPU mip chain and publishes it to the renderer through `RenderTexture` and a texture create command; `Svg` rasterizes a file or inline SVG data with nanosvg at a requested size into the same kind of handle. Both reload in place on change and destroy on removal; images are flipped at publish so the mesh convention of v=0 at the bottom holds.
- `box.material`: `PbrTextures` slots for albedo, emissive, roughness and normal inherited from prefabs; `TextureTransform`, `TextureTiling` with box, cylinder, radial and meters projections, fit, partial tiles and a minimum tile count; `TextureWrap` as repeat, clamp or mirror. The instance carries a UV transform and a packed mode word; a CPU twin of the UV derivation in `src/renderer/tiling.h` is shared with the tests.
- `Surface` gained `keep_source_textures`, `anisotropy` and `texture_quality`; `texture_compression` and `texture_cache` are declared and documented as not implemented.
- Renderer: textures live in 2D array textures per size class (256, 512, 1024, 2048) that grow by copy, with one sampler per class, so instanced batching is unchanged; instances pack four slots into two words. The shader samples with explicit derivatives, decodes sRGB for albedo and emissive, multiplies roughness, perturbs the normal with a screen space cotangent frame, and applies the tiling projection and wrap mode in UV math.
- Assets: `apps/box_app/etc/textures` generated by `tools/gen_textures.py` and hand written icons under `apps/box_app/etc/svg`, embedded in the wasm image.

## Verification
- 403 unit tests across test/core (27), test/transform (46), test/geometry (32), test/render (148) and test/command (150), all passing (`tests.json`, `tests_<project>.json`); the render project grew from 103 to 148 tests (`Textures` 14, `Svg` 8, `Tiling` 15, `NormalMap` 8).
- Visual scenes in `integration/`: `textured` (checker box and sphere, normal mapped box, roughness ramp), `svg_icons` (three icons at 64, 256 and 1024 px), `tiling` (identical world size checkers over 1, 2 and 6 m boxes, a cylinder and a sphere, plus offset, mirror, clamp and fit), `normal_bump` (a normal mapped bump next to a real hemisphere lit alike), and the lighting scenes unchanged.
- Stress benchmarks: `static_100k` 1.41 ms mean and 3.27 ms p99, `material_100k` 1.37 ms and 3.08 ms, against 1.30 ms in the lighting epic; the instance record grew from 104 to 124 bytes for the texture slots and UV transform.
- Microbenchmarks in `bench/` against the lighting epic: `Extract.dynamic_10k` 5.5% slower from the wider instance, nothing else beyond noise. New cases: `Textures.extract_1000_materials` 83 us, `Svg.rasterize_256` 0.39 ms, `Tiling.extract_10k` 459 us.
- Wasm image under `wasm`, open it through the status page Inspect link of this epic.

## Lessons
- WebGPU has no bindless textures; per size class array textures with packed layer indices keep one draw per mesh batch.
- Sampling inside non uniform control flow needs explicit derivatives, and wrap modes folded after the derivatives keep mips correct.
- Device bind group limits are four; the texture arrays share a group with the environment.
- stb_image and nanosvg produce top down rows while the generators put v=0 at the bottom; one flip at publish time keeps both conventions.
- The screen space cotangent frame is correct under WebGPU once the area determinant is computed instead of assumed; a bump lit from the wrong side came from the generated normal map, not the shader. `src/renderer/normal.h` holds the CPU twin.

## Not in this epic
- Texture alpha is ignored by the opaque shader; opacity and blend modes come with the materials epic.
- Textures are square and stretched to their class, layers are never released, no on disk cache or compression.
- Box tiling does not blend across faces, so spheres show three seams.
